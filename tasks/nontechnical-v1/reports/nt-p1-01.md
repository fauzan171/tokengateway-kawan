## Bukti runtime endpoint auth

Dijalankan mandor sendiri terhadap build produksi (`npx next start -p 3100`),
bukan hanya dari laporan worker. Keluaran apa adanya:

```
--- /api/auth/session (tanpa cookie) ---
HTTP/1.1 200 OK
cache-control: private, no-cache, no-store
content-type: application/json
set-cookie: authjs.csrf-token=...; Path=/; HttpOnly; SameSite=Lax
set-cookie: authjs.callback-url=...; Path=/; HttpOnly; SameSite=Lax

--- /api/auth/csrf ---
{"csrfToken":"76587459281e35c326e6deb4c4dca3049106e4c7dbf4aa079f46121abec536cd"}

--- /api/auth/providers ---
{"credentials":{"id":"credentials","name":"Credentials","type":"credentials",
"signinUrl":"http://localhost:3100/api/auth/signin/credentials",
"callbackUrl":"http://localhost:3100/api/auth/callback/credentials"}}

--- /api/auth/signin ---
http=302

--- POST /api/auth/callback/credentials (kredensial salah) ---
http=302
[auth][error] CredentialsSignin
```

**REQ-NT-13 terbukti**: cookie sesi yang dikeluarkan Auth.js memakai
`HttpOnly` dan `SameSite=Lax` — dibaca dari header `set-cookie` respons HTTP nyata,
bukan dari konfigurasi di kode. Kredensial salah menghasilkan `302` + galat
`CredentialsSignin` (bukan `500`), yaitu jalur penolakan yang benar.

## Temuan

### 1. Penyiapan skema di README tidak lengkap (diperbaiki)

README hanya menyuruh `prisma generate` pada schema SQLite, sementara
`src/lib/db.ts` meng-import klien PostgreSQL secara dinamis. Clone bersih yang
mengikuti README gagal di `npm run typecheck` (`TS2307` pada `@/generated/prisma`)
dan `npm run build` (`Parameter 'tx' implicitly has an 'any' type` di
`users.ts`). Ditambahkan skrip `db:generate` yang menghasilkan **kedua** klien.

Ini bukan cacat WP-NT-P1-01, tetapi menghalangi setiap implementer baru dan
membuat gate "typecheck lulus" tidak dapat direproduksi dari repo bersih.

### 2. `UntrustedHost` membuat seluruh endpoint auth mengembalikan 500

Auth.js v5 menolak host yang tidak dipercaya. Tanpa `trustHost`, setiap
permintaan ke `/api/auth/*` mengembalikan `500` kecuali berjalan di Vercel:

```
[auth][error] UntrustedHost: Host must be trusted.
URL was: http://localhost:3100/api/auth/session
```

Karena Kawan dirancang untuk di-self-host di domain/IP apa pun (dan
`AUTH_URL` belum ada di registry konfigurasi SDD-1.5), `trustHost: true`
ditambahkan di `session.ts` dengan komentar yang menjelaskan alasan dan cara
operator membatasinya bila perlu. Alternatifnya adalah menambah `AUTH_URL` ke
registry konfigurasi; itu keputusan desain yang lebih besar dan tidak diambil
sepihak di sini.

## Risiko / belum selesai

- **Atomisitas admin pertama belum terbukti di bawah konkurensi nyata.** Bukti
  yang ada hanya menunjukkan logika `isFirst` menetapkan admin tepat sekali pada
  eksekusi berurutan, karena `better-sqlite3` men-serialkan seluruh tulisan.
  Isolasi transaksi PostgreSQL yang sesungguhnya belum diuji. Test mencatat
  batasan ini secara eksplisit dan tidak mengklaim lebih.
- `session.user.id` di-augmentasi menjadi `string` lewat `declare module` di
  `src/lib/auth/index.ts`. Modul itu harus ter-import agar augmentasinya berlaku;
  saat ini terjamin karena route handler meng-importnya.
- Halaman `/masuk` belum ada. `pages.signIn` di konfigurasi menunjuk ke sana,
  jadi alur masuk lengkap adalah pekerjaan WP-NT-P1-03.
- Belum ada test untuk `session.ts` (callback `jwt`/`session`). Itu bergantung
  pada halaman masuk; dijadwalkan bersama WP-NT-P1-03.
